# Импорт данных из 1С

Раздел готовит почву для загрузки данных из 1С в складскую систему.
Сам импорт ещё не включён — здесь описано, что уже сделано и что нужно
от вашей стороны, чтобы его запустить.

## Что уже готово

1. **Поля для кодов 1С.** У материалов, поставщиков, организаций, блоков и
   операций есть поле `external_id` — код или GUID соответствующего объекта
   в 1С. По нему повторная загрузка находит уже заведённую запись и обновляет
   её, а не создаёт дубль. Поле уникально, поэтому повторная загрузка одного
   и того же документа отбрасывается базой, а не удваивает остаток.

2. **Совпадающая структура документа.** Приход в системе построчный: у каждой
   строки своя цена и своя сумма — как в табличной части «Товары» документа
   «Поступление материалов». Одна строка документа 1С = одно движение в журнале.

3. **Приведение единиц измерения.** В 1С единицы пишут по-разному («шт.», «ШТ»,
   «м», «пог.м»), и без приведения один материал заводился бы дважды.
   Таблица соответствий — в [`src/server/integration/onec.ts`](../src/server/integration/onec.ts),
   функция `normalizeUnit`.

4. **Контракт данных.** Типы `OneCItem`, `OneCCounterparty`, `OneCOrganization`
   и `OneCDocument` в том же файле описывают, в каком виде импорт ждёт данные.

## Что нужно от вашей стороны

Для подключения нужен доступ к базе 1С — что-то одно из списка:

- опубликованный **OData-интерфейс** (`/odata/standard.odata/`) с логином и
  паролем сервисного пользователя, либо
- опубликованный **HTTP-сервис** 1С, отдающий документы в JSON, либо
- регулярная **выгрузка в файл** (Excel или CSV) в оговорённом формате.

Публикация OData делается на стороне вашего администратора 1С:
«Администрирование → Публикация на веб-сервере → Публиковать стандартный
интерфейс OData», затем в правах роли отмечаются нужные объекты.

## Соответствие полей

### Номенклатура → материал

| 1С | Система | Примечание |
|----|---------|-----------|
| `Код` / `Ref_Key` | `materials.external_id` | ключ сопоставления |
| `Наименование` | `materials.name` | |
| `ЕдиницаИзмерения` | `materials.unit` | приводится к справочнику единиц |
| `ВидНоменклатуры` | `materials.category` | если не совпало — «Прочее» |
| последняя цена закупки | `materials.price` | |

### Контрагенты → поставщики

| 1С | Система |
|----|---------|
| `Код` / `Ref_Key` | `suppliers.external_id` |
| `Наименование` | `suppliers.name` |
| `ИНН` | `suppliers.inn` |
| `Телефон` | `suppliers.phone` |

### Организации → организации

| 1С | Система |
|----|---------|
| `Код` / `Ref_Key` | `organizations.external_id` |
| `Наименование` | `organizations.name` |
| `ИНН` | `organizations.inn` |
| `ЮридическийАдрес` | `organizations.address` |

### Поступление материалов → приход

Шапка документа:

| 1С | Система |
|----|---------|
| `Ref_Key` | `stock_movements.external_id` |
| `Номер` | `stock_movements.invoice_number` |
| `Дата` | `stock_movements.occurred_at` |
| `Контрагент` | `stock_movements.supplier_id` |
| `Организация` | `stock_movements.organization_id` |
| `НомерМашины` (если есть) | `stock_movements.vehicle_number` |
| `ФормаОплаты` | `stock_movements.payment_method` (`CASH` / `TRANSFER`) |

Строки табличной части:

| 1С | Система |
|----|---------|
| `Номенклатура` | `stock_movements.material_id` |
| `Количество` | `stock_movements.quantity` |
| `Цена` | `stock_movements.unit_price` |
| `Сумма` | `stock_movements.amount` |

Если присланная сумма расходится с «количество × цена» больше чем на сум,
берётся сумма из 1С: в акте сверки должна сойтись именно она (скидки и
округления 1С считает по-своему).

## Чего импорт делать не будет

Журнал движений неизменяем: загруженные операции нельзя переписать задним
числом. Если документ в 1С изменили, из него получится новая операция —
исправление оформляется отдельной записью, как и при ручной работе. Иначе
остатки на складе разъехались бы с историей, по которой они посчитаны.
